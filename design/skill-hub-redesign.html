Design Principles

What changed and why.

01 · Clarity

One job per section

Discover shows the 3 strongest picks; Featured scrolls a longer list; categories group the rest. No mixed concerns.

02 · Density

Reduce visual noise

Replace icon-heavy cards with hairline-divided rows. Let the skill name and description lead; actions stay small and quiet.

03 · Consistency

Inherit the app theme

All color flows from six CSS tokens. The hub can switch to the host's dark theme without custom paint code.

States

Every interaction has a visible answer.

State Trigger Visual treatment Accent uses
Default Page loaded, no query Full catalog: Discover + Featured + category sections 1 · primary CTA
Search User types in search Hide Discover, filter rows by name / description / category 0
Add User clicks Add Button becomes "Adding…" and disabled until installResult 1 · active button
Installed Skill already on disk Replaces Add with a muted "✓ Installed" label 0
Empty No skills / no match Centered meta message: "No skills match your search." 0
Error Hub server unreachable Inline status banner above the list, with retry ghost button 0

A quieter, faster skill catalog.

This design keeps the existing WebView2 contract intact — it is a visual re-skin, not an architecture change.
