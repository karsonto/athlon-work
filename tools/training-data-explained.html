TrainingData 采集与 AI 能力进化

Athlon Agent 在用户真实使用 Agent 的过程中，自动识别「工具失败被纠正」「超时后继续成功」等高价值片段， 导出 HuggingFace / TRL 兼容的 JSONL，再通过 SFT（监督微调）和 DPO（偏好优化）让模型学会更好的工具选型与推理习惯。

默认关闭 · opt-in src/Athlon.Agent.Core/TrainingData/ ~/.athlon-agent/training-data/

1. 飞轮：从使用到变强

① 使用用户与 Agent 对话、调工具
→
② 检测CorrectionDetector 找失败→修正→成功
→
③ 导出JSONL（SFT + DPO + reasoning）
→
④ 训练LoRA SFT / DPO 微调基座模型
→
⑤ 部署更强模型接回 Agent 循环

核心思想：不是把所有聊天记录当训练集，而是优先采集「用户纠正过 Agent 错误」的片段——这类数据信息密度最高。

2. 如何启用采集

编辑 %USERPROFILE%\.athlon-agent\config\settings.json：

{
  "trainingData": {
    "enabled": true,
    "outputDirectory": "",
    "sampleRate": 1.0
  }
}
字段默认说明
enabledfalse关闭时零开销，不创建采集器
outputDirectory空默认写入 ~/.athlon-agent/training-data/
sampleRate1.0随机采样比例；生产环境建议 0.1

3. 代码里何时触发采集

用户发消息
→
AgentRuntime 工具循环
→
模型最终文本回复
无更多 tool call
→
RecordTrainingDataAsync
→
写入 JSONL
  • 数据来源：内存中的 AgentSession.Messages（不是事后读磁盘日志）
  • 每轮用户消息完成一次 Agent 循环后触发一次
  • 中间只有 tool call、尚未结束的轮次不会采集

4. 采集流水线（代码模块）

CorrectionDetector

扫描消息列表，识别两类高价值模式

  • 工具失败 → 用户修正 → 同名工具成功
  • System 超时/溢出 → 用户「继续」→ 恢复成功

TurnTrajectoryExtractor

把轨迹切片为训练样本

  • SFT：messages[] 格式
  • DPO：prompt/chosen/rejected
  • 附带 reasoning 思维链字段

TrainingSampleStore

追加写入 JSON Lines

  • sft-traces-YYYY-MM-DD.jsonl
  • dpo-preference-YYYY-MM-DD.jsonl

5. 场景 A：工具失败 → 用户纠正（最有价值）

User：「帮我看看项目结构」
role: user
Assistant 调用 grep_files(pattern=.*) — 失败
reasoning: 「先全盘搜索文件内容…」 · tool result: Tool `grep_files` failed.
User：「别 grep 全盘，用 file_list 看 src/ 目录」
CorrectionDetector 识别为修正指令
Assistant 调用 file_list(path=src/) — 成功
同名/同类工具重试成功 → 整条轨迹被导出

导出的 SFT 样本（含思维链）

sft-traces-*.jsonl reasoning 字段 
{
  "messages": [
    { "role": "user", "content": "帮我看看项目结构" },
    {
      "role": "assistant",
      "content": null,
      "reasoning": "用户想看项目结构，我先用 grep 搜索所有文件内容…",
      "tool_calls": [{
        "id": "call_1", "type": "function",

      }]
    },
    { "role": "tool", "tool_call_id": "call_1",
      "content": "ToolCallId: call_1\nTool `grep_files` failed.\nPattern too broad for workspace root." },

    {
      "role": "assistant",
      "reasoning": "用户指定用 file_list 并限定 src/，这比 grep 更合适…",
      "tool_calls": [{

        "function": { "name": "file_list", "arguments": "{\"path\":\"src/\"}" }
      }]
    },

同一轨迹生成的 DPO 偏好对

dpo-preference-*.jsonl

    { "role": "user", "content": "帮我看看项目结构" }
  ],
  "rejected": [

  ],
  "chosen": [

}

6. 场景 B：超时 / 溢出 → 用户「继续」

System：「超过配置的超时时间，已自动停止」
User：「继续」
Assistant：完成剩余分析并回复用户
metadata.source = overflow-recovery · score ≈ 0.7

这类样本教模型：在中断后如何基于已有上下文继续任务，而不是从头乱来。

7. 思维链（reasoning）如何被采集

运行时（始终）

  • 模型 API 返回 reasoning_content
  • 存入 ChatMessage.ReasoningContent
  • UI 展示 + 写入 conversation.jsonl
  • 默认不发回下一轮 API（省 token）

训练导出（enabled 时）

  • TurnTrajectoryExtractor 复制到 reasoning 字段
  • metadata.hasReasoning / reasoningChainLength
  • 失败消息有 reasoning → 质量分 +0.15
  • 训练脚本转为 Qwen3 <think> 块做 CoT 蒸馏

8. 训练如何改变 AI 能力

修正轨迹 + 溢出恢复

学什么

  • 看到类似用户请求时，直接选对工具（file_list 而非 grep_files）
  • 模仿成功轨迹里的 tool 参数写法
  • 通过 reasoning 字段学习「先想什么、再调什么工具」

训练命令（项目自带脚本）

# 依赖: pip install torch transformers datasets peft trl accelerate
python tools/train-athlon-agent.py --mode sft --epochs 5

读取 sft-traces-*.jsonl → Qwen chat template → LoRA 微调 → 输出 tools/model/Qwen3-0.6B_sft_lora/

chosen vs rejected

学什么

  • 同一 prompt 下，提高「正确工具调用」的概率
  • 压低「导致 Error 的工具选择」的概率
  • 比 SFT 更直接地对齐「用户偏好」
python tools/train-athlon-agent.py --mode dpo --epochs 3
# 或在 SFT 基础上继续
python tools/train-athlon-agent.py --mode dpo --load ./tools/model/Qwen3-0.6B_sft_lora

读取 dpo-preference-*.jsonl → TRL DPOTrainer（beta=0.1）

闭环：微调后的模型如何影响 Agent

LoRA 权重合并 / 部署
→
settings.json 指向新模型端点
→
AgentRuntime 调工具
→
更少失败 · 更少用户纠正

Agent 本身逻辑不变；变的是模型在相同 prompt + tools 下的决策质量。用得越多 → 纠正越少 → 数据质量结构变化 → 下一轮微调更好。

9. 质量评分（metadata.score）

修正轨迹会自动打分，用于后续筛选高质量样本：

基础分
0.50
修正指令 > 20 字
+0.15
修正指令 > 100 字
+0.10
失败调用有 reasoning
+0.15
工具参数较复杂
+0.10~0.20

10. 与会话日志的区别

路径内容用途
sessions/*/conversation.jsonl 完整原始对话（含 reasoning） UI 回放、审计
training-data/sft-traces-*.jsonl 高价值切片 + metadata SFT / CoT 蒸馏
training-data/dpo-preference-*.jsonl chosen / rejected 对 DPO 偏好对齐
audit/audit-*.jsonl 工具调用审计 合规，非训练专用

11. 当前限制（阅读代码时请知晓）

  • RecordSessionAsync（整段会话 dump）已实现但未接入 AgentRuntime
  • 每轮结束扫描全量历史，同一修正轨迹可能在后续轮次重复写入
  • 失败判定依赖 tool result 文本启发式（Tool `xxx` failed. 等）
  • Settings UI 暂无开关，只能改 settings.json
